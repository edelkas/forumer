Ok, so i didn't exactly find the time it would take to get to the line, but I did do something simmilar

I added a variable called refreshRate to TrainSim.java that controls the framerate of the applet. You already know the velocity of the train, which is in meters per second.
To control the framerate, in the run method, when it sleeps, replace the 10 with 1000/refreshRate. This is a good thing because when you now go and add the velocity to the train to move it, you can replace t1.incX(t1.getVelocity()) with t1.incX(t1.getVelocity()/refreshRate). This will also control the precision of the velocity, and when exactly the train reaches the line.
For example, lets say refreshRate is 1. Then the applet would refresh every second, and the train would move whatever the velocity was. Now, if refreshRate was 10, then only 1/10th of the velocity is added for every update. The train will still move the same distance as if refreshRate was 1, but now, the comparison to the line is much better. it's calculated 10 times every second, instead of once per second (or whatever your original value was).

So yeah, I made some changes to your code which makes your code A) easier to follow, and B) more precise. The code has a 1:1 pixel to meter scale, which I will try to fix before I call it a night. just ask if you have any questions.

The problem with programming teleporters is that you can't as easily test them out in N without being a constant hassle.
The trick with "teleportation" is that all it is is just a normal bouncepad with high power. The "recieving" pad is placed in just the right position, such that when the game redraws the frame, the ninja is colliding with the "recieving" pad. however, if the original launch pad's power is set just a little bit too high or too low, the ninja will miss, and continue on it's way until it finds itself colliding with a wall or something else, in which it will die.

These calculations are so hard because we don't know how the game calculates/simulates gravity. Because, each frame, just a little bit of down force is applied, so that, over the coarse of the game, the game appears to have gravity. Without knowing how much the game brings the ninja down per frame, figuring out teleportation becomes extremely tedious.
Making teleporters is easy. however, making teleporters in code is much harder.
