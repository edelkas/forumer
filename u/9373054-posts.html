Isn't it possible for all the "bad" high scores to be filtered out of the list automatically?

My idea would be to code an N daemon that would attempt to playback the replay in realtime and cross-check the resulting score against the submitted score. Scores that don't match are tossed, and the submitter's IP can be logged, blacklisted, whatever. Scores that match are forwarded to whatever is in place already for high score and replay processing.

That way, even the geniuses (read: morons) that submit a falsified replay in addition to a falsified high score are caught.

I don't do any AS or Flash stuff, but I'm fairly certain that there are APIs in place for this sort of thing.

Quote: Shark, September 10, 2006 03:35 pm
That would only help with blatantly corrupt high scores.
On the contrary, it would be able to catch *any* corrupt high score. As I described, when a replay is submitted, it would be automatically played back by a computer, and the score resulting from that replay is checked against the submitted score. Because the replay code only contains information regarding user input, any client-side cheating would result in different behavior on the replay computer than on the client.

For any Halo PC players, it is like trying to play a cheat-modified map on a server that isn't running the same cheat-modified map: it might look like you're shooting tank rounds out of your pistol but the server is only counting them as pistol shots.

The real question is, do the costs for running a replay-verification server justify cheater-proof highscores? In my opinion, yes, but, of course, it is ultimately up to the guys at metanet.
