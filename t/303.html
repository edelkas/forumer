His point is that, as I've pointed out previously, determining the rank of a map is an expensive operation - it requires putting every single map into order before you can determine what the rank of any one map is.

Create new "overall_rank" field for map_table
And run:
update map_table
set overall_rank = (select rowid from map_table
order by "rank" descending")
OK, not quite. That wouldn't do anything useful, as the rowid is the same, regardless of the ordering of the rows. Not to mention that query would return every row in the table (which isn't valid SQL), and would set the overall_rank for every row to the same.
The most efficient way to do this would be a stored procedure that gets all maps ordered by rank, then iterates through them, setting the rank number on each map as it goes.
