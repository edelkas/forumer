Using this concept I once implemented a crude game engine that allow a huge series of interactions between different nodes. Originally a crude version of the main loop was implemented in this manner:

// nodez is an array of nodes

Eventually it was written to allow objects to be created and destroyed real time. In fact most attacks in my engine were represented as short lived nodes. Note that this is incredibly inefficient.

The new idea for how I want to implement the engine is based of the concept of event handlers. What I want to do is create a special type of event handler designed to handle the main loop of the game. The handler handles two types of objects: nodes and data. Nodes require two functions: interact and update.

Interact takes in data and checks to see if it is important. If it is, the node stores the data otherwise it throws it away. Then when the update function is called the node checks any data it saved to see if it modifies its new state then it resends itself to the event handler (or not if the node has died). New nodes are created when needed during this phase as well.

Example Engine

class Engine {
Node[] nodez;
Data[] datum;

public void getNode(Node e) {
nodez.add(e);
for(int i = 0; i < datum.length(); i++)
e.interact(datum[i]);
}
public void getData(Data e) {
datum.add(e);
for(int i = 0; i < nodez.length(); i++)
nodez[i].interact(e);
}
public void update() {
Node[] e = nodez;
datum.clear();
nodez = new Node[];

for(int i = 0; i < e.length(); i++)
e[i].update();

e.clear();
}
}

Hi mattk210,

Thanks for welcoming me and that important question.

I want to use Node Gardens as a new way of processing data and events for a game. The way I want this particular version of the engine to work is based off the concept of event handling. The original idea was that all in game objects and data are represented by "events". Each time the game updates all game "event" objects are allowed to process any data they have received and act upon by any or all of the following:

1.) Resend itself to the "event" handler
2.) Send new data to the "event" handler
3.) Create a new "event" object and send it to the "event" handler

Something important about this system is that in-game objects must resend themselves to the event handler if they wish to live from loop to loop in-game. Another important point the only way for objects to know about each other is to send "event" packets recording information about themselves. This lets you create nodes that just go from loop to loop silently listening to the data stream. Coding easter eggs has never been easier. And finally creating objects is simply initiating a new object and sending it to the "event" handler.
