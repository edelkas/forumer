I'm still waiting for my friend, he might be busy right now. But I have some good news:

In v1.3, expect an even better compression! Here's what else might happen to the code before being completely zipped:

At the beginning of each object code, you see #^ and # is a number from 0-12. These will all be replaced with a unique character, so that !number^ will be replaced with a character that doesn't recur anywhere else in the code, except for other !number^ things. This changes as many as 4 characters into one.

All numeric values will be replaced with base-64 before compression.

Something might happen with the tileset code, but I can't promise anything amazing. Maybe just removing the | that separates objects from tile code.

#455451 26 2008-07-28T05:38:39Z Gforce20
Okay, I'm going to revive this project with a new plan in mind.
Rather than simply turning it from 8-bit to 7-bit, I'm going to compress the file based upon level data's structure, not just the fact that it's ASCII.

Tile data will be 5-bit indexed, unless 33 or more of the 34 possible tiles are used, in which case it'll have a 1-bit header for 1's and 0's (blank and solid tiles) which will be further compressed, probably based upon repeating patterns.

The object data will work quite differently. Most objects look something like this:
0^32,150!
Each section can be compressed individually. The first section (object type) can be compressed down to 4 bits (I think... I forget how many objects there are O_o), the coordinates can be converted into 10-bit integers, and any extra data like drone paths can be compressed as well using similar methods.

Any questions/suggestions for this new version? It might be coded in PHP, rather than Liberty BASIC, since not many people seem to have Liberty BASIC installed.
