To be honest, that's some pretty messy code. I would suggest a complete rewrite but barring that, an array of shots should work -- have a shot movieclip in your library, attach it to the stage when a shot is fired and store it in a variable in the array. Then for hit detection loop through the array.

setting up the array:
var shotArray:Array=new Array()

assigning a movieclip to an element of the array (replace i with a number)
shotArray[i]=_root.attachMovie(ID, name, depth)

You may not have understood that, try reading up on it or i can walk you through the correct way to program this game.

But really, you should look up some good programming principles and stuff. Movieclips and rendering stuff on screen should be discrete from the logic of your game. Also, I find it much more manageable to have all your code on the main timeline and not on individual movieclips.

#456626 4 2008-07-31T13:31:34Z Decoy
Imagine you have a group of objects. You know their names (for argument's sake, Apple, Banana and Pear). If you wanted to do something to all of them one after the other, you could hard-code it. Something like doStuff(Apple); doStuff(Banana); doStuff(Pear); etc. But what if you have a fourth thing? An array is a way of organising similar objects so you can do operations on them one at a time.

So on the main timeline, put the code
shotArray = new Array();

Then, when you create a new shota instance (line 4 of the cursor_mc code), put the instance into the array by using
this.index = shotArray.push(_root.shota.duplicateMovieClip( "shota"+shotacount, shotacount+7000)) - 1;
We use the same code to add the movie clip, but we put it into the array using shotArray.push(), and store the index of the point in the movie clip's value this.index (which is a variable we made up).

You also have to add some code to your main timeline code:
remove = function(bul){
    bul.removeMovieClip();
    shotArray.splice(bul.index,1);
};
and then change all the lines in the bullet code that say "this.removeMovieClip()" to "remove(this)".

Lastly, we need to make it so that your detection works on the bullets in their array. Change the code on enemya to:
onClipEvent (enterFrame) {
for(var i = 0;i < shotArray.length;i++){
    if (shotArray[i].hitTest(this)) {
        _root.score += 1;
        _root.enemyahp -= 1;
        remove(shotArray[i]);
    }
}

I think that should work, but note that it will get slow extremely quickly with lots of bullets and enemies! It has to do [#bullets] hitTests per enemy, so a total of [#bullets]x[#enemies] hitTests per frame. But really, it's as fast as such a system can be before optimising while still using hitTest becomes farcical.

yeah, that's a much more understandable explanation than mine. Expanding on that, you can very easily replace hittest by comparing the squared distance between the two objects to a precalculated length.

Basically, if your bullets are just a point, and the enemies are circular-ish with a radius of 50 pixels, the distance code is:

var xdist=bullet.x-enemy.x;
var ydist=bullet.y-enemy.y;
var dist_squared=xdist*xdist+ydist+ydist;

that's pythagoras by the way.

so if dist_squared is less than 50 squared (2500), then we have a collision

I hope that was more clear than my last (very convoluted) explanation.

Not quite. That + should be a *.
In order to use this instead of hitTest, make a function like this:
function hitTestCircles(circle1, circle2){
var xDist = circle1.x - circle2.x;
var yDist = circle1.y - circle2.y;
var distSquared = xDist*xDist + yDist*yDist;
var combinedRadius = circle1.radius + circle2.radius;
return(distSquared <= combinedRadius * combinedRadius);
}
Define your bullet's radius to be 0 and your enemy's radius to be something reasonable. This must be done within the objects' movie clips.
