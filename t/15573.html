#291903 8 2007-01-30T22:21:56Z Exüberance
Not if it's NaN'd.

I believe the turret check to see if there is an active instance of N that collides with an imaginary line between the cordinates (turret.x,turret.y) and the co-ordinates of the point where a collision with a tile first occurs along that line.

When it is NaN'd, it automatically detects a collision with N, because it doesn't recognize point (NaN,NaN)
So instead of returning an error, the function returns 'true' (or false if it checks for the absense of a collision)
and N gets pwned.

Why It can go through tiles, I'm not quite sure. It all depends on how Flash handles NaN as a value and NaN as an arguments/return value in a function



When you watch the turret outside the level, and look at it's lock-on targeting thingy, it appears to be mostly located at position (N's x co-ordinate , NaN) while the turret is at position ( NaN, NaN ) In the case of a drawing location or position placing, NaN acts as if it is 0, which is why it appears to be in the top-left corner. It actually is not there, it is at position (NaN,NaN), not (0,0)
