#383440 2 2007-11-26T20:09:44Z Raigan
hi,
A level editor is just a tool for creating or manipulating data. Ultimately, your game needs some data that describes a level. In N this is a 2D array of tile shapes (stored as a 1D array) and a list of object definitions.

First, make your game -- at some point, you'll have to figure out what sort of data the game needs. Once you know this, you can make an editor to help you create and modify this data. Depending on the type of game, you might just need some sliders or text fields; it might be more useful to display the data in a different form, such as how it will appear in the game rather than as text.

Um.. i'm afraid I can't help much more than that. The editor can be as complex or simple as you like -- for instance, if you use text as your data format, you can just use notepad to edit levels.

Definitely get the basics of the game working before you spend time on the editor.

#384085 10 2007-11-28T17:14:59Z Raigan
This is sort of what I was getting at with the "game first" comment -- you need to figure out how the game will actually work before you really need to worry about preparing data for it to work with.

If you download the source code from our tutorials you can see how our system works: http://www.harveycartel.org/metanet/tutorials.html

However there are other ways to do it; basically you have a grid of tiles. The tiles can be represented explicitly as actual objects with properties (position, shape, etc) or implicitly as a single number which describes the tile type (this number would then be used to look up information about the shape/etc for that tile; the position in the grid would indicate the tile's position).

tonypa has a great set of tutorials you should definitely read through: http://www.tonypa.pri.ee/tbw/start.html

here's another tutorial, it shows a non-grid-based way to do things: http://www.strille.net/tutorials/part1_scrolling.php
