Hello, I am here to make a guide on coding for n levels. You know when you open the debug menu and you see that massive text window that has all the level data? Ever feel Overwhelmed? Well I am going to help you understand that jargon. there are 2 main parts of the level data we shoud look at, the tile data and the object data. its organized like this. But first, why should I bother? Well, theres a number of features in N you cant access, for example, did you know launchpads can have a different amount of power?


GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWRA
GARRSGD%@&%TWUH4556igssrEJH5JWEHWR|<OBJECT DATA HERE>

The jargon is the tile data, each square in the map has a value in there somewhere, whether its empty or full, curvy or sharp, or even coded in and buggy. then we have a |
symbol, this separates the level data and the object data. Finally we have the object data. Too explain this lets make an empty level:

it should look something like this:

0000000000000000000000000
0000000000000000000000000
0000000000000000000000000
000000000000000000000000|

granted, the real things alot larger. Now put a ninja in the lower right corner. Look at the code now:

0000000000000000000000000
0000000000000000000000000
0000000000000000000000000
000000000000000000000000|5^756,564!

see the added text? the 5^ defines what type of object it is, and the next two numbers are variables, all variables are separated by commas. In this, case, these two variables are the coordinates for the ninja, which say where he will be placed. the first two variables are always the x and y coordinates which say where the object is placed. Finally, look at the end, theres an exclamation mark. This means this object data has ended, and anothers should start, so the next <number>^ isnt a part of the last variable of the last object. Other objects can have more variables.

Now, we go onto code errors. If the game finds an obvious error in the level code when loading a level, it fixes it. But this usually only works if their can only be one way the code can go, for example, someone putting an 1(seeker on) in a laser drones spot for seeking(all drones use 6^), while only zap drones can seek. But more often, when there can be more than one value that will work, the game makes a NaN. This means theres a bug in the code and the game skips it, and can cause some rather buggy things too happen, for example, making a drones movement code some number thats not valid, like 10, will make it stand still and its "eyes" will fall too the bottom, like they are being pulled. Also, if you then check its code, it will say it NaN where the movement variable should be. And thats all you need too start too learn n code editing, If I were you I would find vikings n disections as well, they are a very usefull reference.
