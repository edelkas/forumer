What you should do is run the replay (The CURRENT REPLAYS RECORD KEYSTROKES AND NOT IMAGES AS MENTIONED) and when running the replay, record a "video".

This video would JUST be N, and the information is dotted points on where he turns (Think vector graphics here) and also what stances. This is a serious coding job right here.

This would then be stored with (a fairly large I'd think) secondary replaycode. This code you could then use to get your transparent, non-CPU-demanding, second ghost ninja into the game that you're playing.

Also, the code can be used on ANY map as it isn't map specific unlike the replay. This is a graphic recording and not a keystroke recording.

The drawback of this, apart from the work required (Coding and such), is that you have to watch the replay first to get the graphical data.

-- I don't think this will be happening, although this is probably the only workable idea without having to calculate two physically simulated ninjas, mainly because of the massive codingwork required to take all the graphical points to use and the code required to later screen them back again into workable graphic with not-too-much replaytext.
