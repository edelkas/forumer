Motherlode on Moon, experience low gravity here
http://numa.notdot.net/map/120522

All credits go to M&R for making such a great game.

This player mod is built for those map makers who love the original N

For those who used NReality map, please add the tag "NReality"

For those who used image, please add the tag "image-map"
For those who used drone mod, please add the tag "droneMod"
For those who used player mod, please add the tag "playerMod"

WARNING WARNING WARNING WARNING
Most N players adapt to the origina Ninja Control. Any modification to the relation between ninja and the environment could create hateful playing experience.
My concern is, especially to the highscorers, if there are too many nreality playermod map which alter the way they control the ninja, they may feel more reluctant to try new playermod map.
A successful game usually is a game where those skillful player can precisely and accurately control how the avatar (ninja here) response. If you change the ninja attribute here, it may lower the overall playing experience of N.
WARNING WARNING WARNING WARNING

NReality Map data structure:

$MAPNAME#AUTHOR#TYPE#leveldata|objectdata|bgImage|fgImage|NRealityMapType|droneMod|playerMod#


Here are the attribute list, which I haven't tested all of them, please help me to test them one by one and report the result :

r
maxspeedAir , default = r * 5.000000E-001;
maxspeedGround, default = r * 5.000000E-001;
groundAccel, default = 1.500000E-001;
airAccel, default = 1.000000E-001;
normGrav, default = 1.500000E-001; I suggest you to set g equal to the same value too. e.g. normGrav,1;g,1
jumpGrav, default = 2.500000E-002;
normDrag, default = 9.900000E-001; I suggest you to set d equal to the same value too. e.g. normDrag,2;d,2
winDrag, default = 8.000000E-001;
wallFriction, default = 1.300000E-001;
skidFriction, default = 9.200000E-001;
standFriction, default = 8.000000E-001;
g, default = normGrav;
d, default = normDrag;
jumpAmt, default = 1;
jump_y_bias, default = 2;
max_jump_time, default = 30;
terminal_vel, default = r * 9.000000E-001;

#428261 50 2008-04-14T01:48:50Z player03
Here are some more:

playerMod:
|||||max_jump_time,125;jumpGrav,-0.06;jump_y_bias,-7; makes for sinusoidal walljumps. However, it also causes the ninja to die if he jumps from the ground. You can also replace 125 with 75 and -0.06 with -0.1 for faster jumping.
|||||jump_y_bias,47; will cause jumping to teleport the ninja up multiple tiles. You can place a downwards-facing one-way pad at multiple locations above the ninja to stop him, though you may have to experiment with them a little.
|||||skidFriction,1;normDrag,0.9995;d,0.9995;terminal_vel,120; removes friction (and compensates for the side effects).
|||||skidFriction,1.03; causes the ninja to speed up whenever he is sliding on the ground.
|||||skidFriction,Infinity; causes the ninja to stop interacting with anything whenever he skids to a stop. It's not very usable, but it's interesting.
|||||wallFriction,1.06; causes wallsliding to either stop the ninja or accelerate him violently upwards, depending if the ninja was falling slowly or quickly. This is not recommended for walls more than 1.5 tile-lengths from top to bottom.
|||||standFriction,200; gives the ninja a burst of speed whenever he would come to a stop.
|||||jump_y_bias,0;jumpAmt,4; makes perpendicular jumps more perpendicular and makes walljumps act like regular perpendicular jumps.
|||||groundAccel,0;airAccel,0; forces the player to play the map with only jumps (though they can use the arrow keys to keep from skidding to a halt quickly).
|||||groundAccel,-0.15;airAccel,-0.12;skidFriction,0.99; essentially reverses the ninja's response to the left and right keys. It does, however, have some unavoidable (but minor) side effects.

droneMod:
||||0,speed,-1; creates drones that back up in a straight line without stopping or turning when they hit anything. If they would normally turn at the start, they turn first and then start backing up.
Notes:
1. You can change the -1 to any other negative number to change the speed at which they move backwards.
2. This works for any type of drone.

||||2,chaingunRate,0; creates a very hard-to-avoid chaingun.
||||2,chaingunRate,0;2,chaingunPrefireDelay,0;2,chaingunPostfireDelay,0; creates a nearly-impossible-to-avoid chaingun.
||||1,laserRate,3;1,laserPostfireDelay,0;1,laserPrefireDelay,7; will create a fast laser which will force the player to keep running or die.

Unfortunately, chaingunMaxNum and chaingunSpread appear not to work. However, if they did, ||||2,chaingunRate,0;2,chaingunMaxNum,100000; would probably create a chaingun that never stopped rotating/firing.
It also seems that laserLen has no effect. Hopefully, Unreality will be able to change some code and fix this.
