I had some thoughts about Ned.
1. It is very slow due to the fact that it uses the N engine.
2. It has no output to a file, only to textboxes.
3. You don't have any possibility for real in-game testing, only debug mode.

So I thought it was time for another trial to make a good external editor. I called it Ned++ like C++. My possible solutions:
1. By using a normal window and Windows' fast API functions, speed can be increased significantly.
2. Like in N Art Maker, you save your level directly to a file or ...
3. ... to your existing userlevels.txt file making testing easier by just using N's userlevels mode.

And... I'm going to integrate N Art Maker into Ned++. (Perhaps also a better version of N Pathfinder.)
But it's a long way to a good level editor. So I'll comment it here and you can test my program as it develops.

You find the newest version always here at the top.

The current version 0.15 contains tile setting, input from and output to file and a manual. Help me to translate it into your mother-tongue! For details see readme.txt. (At the moment, we have English and German.)

And BTW I'm using Visual Basic 5.

Update: Some guys sent me translations for Arabic, Finish, French, and Russian (Translit). These language versions are now included in the package.
Yet another update: I have created an installer for Ned++. It allows you to select which components (such as specific languages) you wish to install, and can create shortcuts in your start menu. You can download the installer below. (It had to be packed in a zip file because exe files are not accepted.)

Update: I have worked on the implementation a bit, now it should work a bit faster. (Please report here how fast it goes for you.) Also I added some gridlines, like in Ned (but not so many types), and the translation module has been completely rewritten, allowing dynamic load of translations. The new version number is 0.20.

#85598 3 2005-07-23T15:33:04Z LoD
OK i forgot a manual so here's how it goes:
The big picture is the map you're editing. (It's same size as in Ned because the tiles have to fit.)
Below you see a picture box which contains all possible tiles. (You find the picture in images/tileset.bmp.)
If you move your mouse over this picture box a cursor will appear highlighting the currently selected tile. If you click now, the selected tile will be loaded in one of the three boxes in the frame below (depending on which mouse button you pressed).
After having selected some tiles this way, you move your cursor up to the map and simply click on it. Depending on which mouse button you press, a tile will be set.

I thought it was clever because you can easily select up to 3 tile types, e.g. you bind the full tile to left and the empty tile to right, then you can create simple forms and if you clicked on the wrong point you can easily delete the tile. (Needs some practice, but Ned does, too.)

#129238 48 2006-01-02T15:01:38Z LoD
@ all who have problems with "comdlg32.ocx":

Search in the Explorer for this file: "C:\Windows\system32\comdlg32.ocx" (or "C:\Windows\system\comdlg32.ocx" on Win9x and WinME). Then look for information about the version of this file. I have 6.0.84.18. If you have a version "4.x.x.x" or below or if this file even does not exist, try the following steps:

Download the file http://activex.microsoft.com/controls/vb5/comdlg32.cab. Extract this archive, right-click on the inf file in the Explorer, and choose "Install". Now, reboot your system and retry to start Ned++.

If Ned++ does not run properly, search the ocx file again in your system(32) folder. If you find it, look for the version. If it's not 5.1.43.19, something went wrong during the installation process. In every case, tell your experiences here (including your OS version, the file version you found, and how it worked).
