OK do you want to count the r's and n's or do you want to decide wich one appears first? Beacause in your first post you said that you have to determine which appears first.

indexOf() just gives you the position of the first appearal of that character.

If you want to count characters you have to make a loop over the whole String and check every position wheter it is the searched character.

For exampe:

String test = new String("ingredient");
integer position = test.indexOf('n');

Now position will have the value 1. Because the n is at positon 1.

String test = new String("ingredient");
integer nCount = 0;
for (int i=0; i< test.lenght(); i++)
{
  if (test.valueOf(i).equals('n'))
    nCount = nCount+1;
}

Now nCount will have the Value 2 because there are 2 n's in this word.

To shorten your code you can also call:

test.toLowerCase();

then the whole word is lowercase and you don't have to count the upper and lowercase characters and add them later.

Oh and are you sure that you get 0 r's and 3 n's by entering train because this looks more like rain. (r at the 0th position and n at the 3th)

hth

#433496 14 2008-05-03T07:41:35Z rennaT
This is some impressively poor code. The reason the StringBuffer isn't being properly initialized is because there's no variable for it to be stored in. You're trying to store the StringBuffer in a String variable.

First things first: Anything in the java.lang package is part of the core Java language and doesn't need to be imported.

Secondly, it doesn't seem important now but using the conventions for Java names will make your code easier for you and others to read. Classes are capitals. Variables are lowercase unless it's final and never going to change throughout the entire program and then it's all capitals.

ex:
String is a class or an object.
We create a String called pie.
pie is the variable so it's all lowercase.
String pie;
Then we want to throw something in the pie variable.
String pie = new String ("Eat me!");
That's what's known as initializing the instance of the variable. You create the new data with the new command and the Class that follows the new command must (at least for the purpose of this lesson) match the Class of the variable. Read that again as it was where you ran into problems with the last program.

Thirdly, you'll never learn anything if you get us to write your code for you but I just can't bear the thought that this code is running somewhere so I'mma rewrite it the way I would have written it from the start and then, maybe, you use that as a template.

/**
 * @(#)Palindrome.java

import java.util.Scanner; //imports the scanner

public class Palindrome {
        
    public static void main(String[] args) {
       
     // creates the Scanner object
     // notice that instead of declaring static instances of the input
     // and output streams, I just used the ones that are already in the
     // runtime by default
     Scanner wordScanner = new Scanner (System.in);
     
     // explaining what input you're asking for is just good form
     System.out.println("Enter the word to be tested for palindromitude.");
     
     // gets the next word entered and puts it in the "input" variable
     String input = wordScanner.next();
     
     // takes the input, flips it around and spits it back
     // notice that I've tacked the toString() method on the end there
     // what I did by doing that is I just saved myself a step
     // I could have written the following instead
     // StringBuffer buffer = new StringBuffer(input); makes the StringBuffer
     // buffer = buffer.reverse(); reverses the contents
     // String reversed = buffer.toString(); turns the StringBuffer back into a String
     String reversed = new StringBuffer(input).reverse().toString();
    
    	// when you're comparing String objects, you have to use the
    	// stringA.equals(stringB); method
    	// objects are way different from just normal numbers
     if(input.equals(reversed)){
      	System.out.println(input + " is a palindrome.");
     }else{
      	System.out.println(input + " is not a palindrome.");
     }
    }
