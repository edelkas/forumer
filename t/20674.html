#389783 2 2007-12-15T23:07:35Z Raigan
for one thing, there are two parts to this -- representing it visually (drawing the shadowed regions), and representing it logically (being able to test if a point is in shadow).

for the visuals, you can use stencil shadows (as seen in gish); this is the same idea as doom3's shadows, except in 2d. if you google around you should be able to get the idea.

for logic, you don't need to explicitly construct the shape of the shadow/lit region -- you can just cast a ray from the query point/object to the player and see if it hits anything before the player. if so, it's in shadow, if not then it's visible.

at least, this is one way of doing it. our friend jon made a game in java that used this sort of technique.

#389965 5 2007-12-16T16:52:24Z Raigan
sorry -- i failed to notice the part where you mentioned this was in flash!

this makes it more difficult if not impossible; stencil shadows are sort of a cheat since they let you implicitly calculate the shadowed area -- they're a process whereby you end up with the result you want, without having to EVER explicitly figure out the exact shape of the shadowed region. the basic algorithm is: find all the geometry near the lit region (cone shaped in this case), extrude geometry out to infinity in direction away from light, draw extruded geometry into stencil buffer, draw fullscreen shadow masked by stencil buffer (or, alternately draw the lit scene masked by the stencil). gish uses this for box shadows.

the only thing i can think of is to use a portal-rendering type approach, where you start with a single frustum (truncated pyramid in 3d, parallelogram in 2D) and recursively clip it against geometry. this will require you to split your levels into convex chunks, and is almost certainly going to be rather work-intensive. i can't seem to find any good tutorials on google, but there should be lots since this sort of method was used for rendering 3D games..

about determining visibility, that's true; since this is used normally for vision/AI tests and bullets this is usually fine -- in the former case the head of the enemy is typically centered on the object, and in the latter the object has no size. i'm assuming top-view.


one alternative you might want to look into is using a grid-based solution, which is very common in most roguelike games (doomRL for instance); this should be fast enough in flash, however it's not exactly the same as what you want, since it will require the levels to be tile-based.

oh wait -- rereading your post, you want to use this for moving enemies! that might not be feasible, typically this sort of thing is used with static level geometry. certainly you could do it outside of flash, in flash it might be asking too much
