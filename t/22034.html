#423003 22 2008-03-29T05:39:05Z Condog
Here's what i got:

speed : the higher the number, the faster it goes. However a high enough number will result in the drone not moving, as it moves enough pixels to move to the spot it was in. As the number approaches this point, the drone will appear to slow down. As gets further away, it will speed up.

fireDelayTimer - no visible effect

prefireDelay - no visible effect

postfireDelay - no visible effect

laserPrefireDelay - no visible effect

laserPostfireDelay - The drone will remain immobile after it has fired for a varied time.

laserRate - no visible effect

laserLen - no visible effect

chaingunPrefireDelay - The drone will remain immobile after it has targeted, but before it fires for a varied time.

chaingunPostfireDelay - The drone will remain immobile after it has fired for a varied time.

chaingunMaxNum - no visible effect

chaingunRate - The rate of fire increase/decreases depending on the number used. As it approaches one, the speed will become faster, until it reaches a speed so fast it will immediately kill the ninja. As it approaches infinite, it will appear to lag between shots. As normal the shots will target the place where the ninja was when it started to fire. Thus, the larger numbers will cause it to be very unaffective, whereas lower numbers will result in a 100% death rate.

chaingunSpread - no visible effect

#449887 63 2008-07-01T03:24:34Z Unreality
Sorry for double post (I honestly don't think double post used up that much server resources tho), but this is a critical info to the mod:

you can only input Numbers as the value. You can input "3", "0.5" etc, but if you put "tiles.xw * 5.285714E-001" etc the value will become zero.

i.e. "6,closeAimSpeed,1" is correct,
but not "6,closeAimSpeed,5.000000E-002",
not "6,outerThreshold,tiles.xw * 8"

Update

http://nmaps.net/129343 <== redrum, redrum, redrum, red drone!!!!!!!

Now NReality supports the following modification to the graphics(movieclip in terms of flash) of the drones/objects:

_xscale ( in %, e.g. 0,_xscale,50 will return a 50% width drone, graphical only, not the 'actual size')
_yscale ( in %)
_alpha (transparent from 0 to 100%)

and

_color
this is not a native flash attribute, I introduce it to the clip, you can set the color like this :
0,_color,100.100.0.0.0.0.50.0
which made the zap drone become red and semi transparent

as you can see, the values are connected with dot "."
red%.redMod.green%.greenMod.blue%.blueMod.transparent%.transparentMod

% are from -100 to 100
Mod can range from -255 to 255 I think... seems can be more than that

so
0,_color,100.100.0.0.0.0.50.0
remain its original 100% red, and add 100 to its red, and removed all its original green and blue, plus making it 50% transparent

Keep in mind this update only affect the drone/object appearance, and probably won't affect its ACTUAL SIZE.

As you know, when you scale the drone/object very big with a big "r", the graphics seems to be out of scale, at this moment you can use _xscale and _yscale to fix that.
