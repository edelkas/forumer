Sounds great! We're using AS3 to prototype some stuff, someday in the future we'll hopefully find time to rewrite N using AS3 as it's soooo much faster.

I'd really recommend against a "delta-time"/non-fixed-step simulation, as it then becomes nondeterministic; a fixed step size doesn't mean that the game will run at different speeds, only that you update the world in consistantly-sized steps.. sort of like time is quantized.

see for instance: http://www.gaffer.org/game-physics/fix-your-timestep/

#362479 24 2007-09-05T21:19:06Z Raigan
I don't know -- I think it's possible that a slightly more general method could be just as fast or faster than our old tile-based method. Specifically, you end up having to do a lot of tests to get things behaving nicely in all situations -- i.e the part of the code where you test vs horizontal and vertical neighboring, then (possibly) test vs the diagonal neighbor.

It seems like a box- (or circle-)-vs-lineseg test should be just as fast as box-vs-tile, but that would allow for more general shapes. You'd lose all the "edge-state" stuff, but i don't know that that's actually helping it run faster -- in AS3 it could be more work than it's worth. It was added as a way to get smooth sliding on long horizontal/vertical surfaces, but if you're using a lineseg-based method you get that anyway.

Probably you shouldn't listen to me though, right now in our AS3 simulator collision is a _huge_ bottleneck!!
