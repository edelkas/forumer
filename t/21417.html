Hey guys, been a long time since I last stuck my neck in this part of the woods. Did absolutely nothing to do with programming since my last post and recently started using flash again. Reading this tutorial gave me some inspiration, so I began coding again. The idea is that the game will end up as an undead-themed survival game. You, the blue square, will have to evade and eventually destroy growing hordes of red and (even more shockingly) green squares. You have at your disposal several badly-animated spells of minor irritation. I might put in better graphics if I feel like it, but I'm lazy right now. Currently all drawing is done using Flash's API. I'm better at drawing with code than I am with Flash itself.

I realised that the tutorial's hitTest methods were antiquated and inadequate, so I used the SAT method (a simplified version since it only deals with points and AABBs, maybe eventually circles). This allowed me some additional control over the environment, for example being able to add and remove obstacles on the fly. The current version of the game is very simple. There are no goals yet and the health system is entirely for show as there is nothing that does damage. However the spell system works properly. The yellow bar, for those who are wondering, is the cooldown bar. Certain spells activate longer cooldowns.

There are currently 7 spells for you to play around with to learn the ins and outs of my engine and give me critique or advice (all aimed with the mouse relative to the player centre, selected with the number keys).
1. Push. The spell pushes the enemy away from you. Note that it is raycasted properly, so it will not penetrate enemies or platforms unless they are flagged to ignore it (e.g. the 'window' up the top). In the current version of the game the rays are of a fixed length. In this version they have a maximal length only.
2. Pull. The opposite effect of push.
3. Smash. A short-ranged, stronger version of push.
4. Force push/cone push. Creates a cone of rays that push the enemy away. This spell doesn't penetrate the window. I'm currently modifying the raycasting slightly so that they will be able to hit enemies, pass on their effect and continue.
5. Shield. A circle of rays that push the enemy away, close range. Doesn't penetrate window.
6. Teleport. You guessed it. Teleports your box to the end destination. Currently hits enemies, the version I'm using (which I'll upload tomorrow) doesn't.
7. Ghost mode. Turns the player into a ghost. Has a mana upkeep cost. Allows you to travel through platforms/windows (but not the walls around the edge). The current version of the game has 'ghost obstacles', which solid forms can move through but ghosts can't. Player will turn back to normal upon exhausting their mana supply. The current version also features a colour change during ghost form.

Also, press "q" to activate unlimited mana and "w" for massively reduced cooldown. Note that ghost form will over-ride these changes (note also that this is intentional ).

Things I am planning to implement: multi-sampling for collision detection (so that you can't shunt enemies through the window for example), AI for the enemies (including attacks which deal damage), 'create obstacle' spells (ethereal and solid forms), a character advancement system, 'toggle ethereality' spells (for enemies and statics), perhaps ghost-specific spells. In the very distant future, also friendly units and multiple levels (or change the engine so that it supports one much larger level).

So, thoughts? I'll release an updated version tomorrow with the features I mentioned today (as well as whatever I think of during my sleep). If demand is high enough I just may release a well-commented bare-bones version of the engine to help people learn the ropes.

#409349 7 2008-02-14T08:38:41Z Decoy
It's like mattk210 said, I created two classes, Ray and Cone. The Ray class contains the instructions for each ray's actions, for example stepping it forward, checking for collision, rinse and repeat, as well as outcome of collision with various objects. The cone class simply creates a number of rays with equal angles between it and (using flash's drawing api) connects the dots and fills to make a cone shape.

All you need to do the raycasting is a point versus object collision detection system. Then you create code to the effect of:
1. Move point forwards along its direction vector
2. Does the point end up inside a blocking object?
a. If so, return which object it is, the final position of the ray and tell the global event handler what to do
b. If not, repeat steps 1 and 2 until you reach your destination

The tutorial I linked in the first post gives working code for such a system, but uses hitTest().

This next update comes much later than the others because I've been somewhat busy in real life.
Pre-alpha v4
I'm not exactly sure what changes I've made since the last version I put up here either, but I'll give you some idea:
The enemies now appear in the generator (purple thing). They spawn to a max of 3 and from a range of different archetypes.
There is a new type of enemy that you can't ghostify, the hulk. It moves slower than both the zombie and the ghost, but does more damage than both.
Ghosts have a spell that they cast now. It slows the player down drastically for 3 seconds (but they can't cast it very often). I don't have an animation for showing the slowdown yet (I'll add a debuff bar in the next version I think).
You'll notice pretty quickly that the player has only a small sphere of sight around himself now. A new player spell (9 on the keyboard) doubles the size of this sphere temporarily. I decided not to use my cones for the light, as it was very cpu-intensive and not terribly beneficial.
Another new spell (0 on the keyboard) lets you create a small light at the end of a ray. You can only have one at a time, and only for a limited duration.
I almost forgot to mention that the enemies have a rudimentary AI now. They will pursue the player when he is in their line of sight (ghosts can see/move through walls), and otherwise move randomly.
Touching enemies that connect with you causes damage, as well as being too far inside walls (for example when you unghost).

I also changed the way the drawing was done to a centralised method, which allows me to draw the HUD on top (among other things). Play around with it, give me feedback. Once again, I know that the cones are extremely slow. I think I'm going to drop them altogether.

#411143 13 2008-02-21T07:10:58Z Decoy
This update is a huge one in many ways. Gameplay itself is practically unchanged however (not that there is actually any gameplay at this point). You can now use WASD for movement. You can now pause the game with P (unpause by clicking on the button). The 'cheat codes' are now SHIFT+1 and SHIFT+2 (for infinite mana and no cooldown, respectively). I smoothed the AI out a lot so that they don't leap, they shuffle appropriately. And, the best part of all... I completely changed the raycasting code so there is now not the slightest amount of lag. mattk210, you might be interested in the changes.

It works really well for short rays, but regrettably I've only bothered to make the AABB raycasting at this point. Basically, instead of 'stepping' the ray along many times until it collides with something (the old algorithm I described in an earlier post), it now calculates the point of collision based on a series of early-out boolean tests. I'll comment it and post the source if anyone wants it. It's not particularly innovative, just much more efficient for games that don't use the full gamut of shapes. I'm going to add additional shapes soon, starting with circles and then NAABBs. I've already worked out how to do the calculations for those shapes, just haven't coded it yet.

So, enjoy Pre-alpha v5. Please let me know about any bugs you find.
