#136594 13 2006-01-28T07:17:38Z Ixi
Quote: jtbandes, Jan 27 2006, 11:55 PM
Quote: Maniac, Jan 27 2006, 11:39 AM
Basically, doors change the state of the edges of the grid, and can thus only be placed on tile edges.
But tiles change the state of the grid edges, too, and there are tiles that are only half-on a grid square. Heck, there are tiles that are only on ((4*r_squared - pi*r_squared)/4)/4*r_squared of a grid square! I don't understand why this isn't possible.

Because, from my understanding, each of those shapes is hard-coded. There is currently no way to dynamically generate the proper collision behavior for the very large number of possibilities that pixel-precise door placement would allow.

Mines are different because they don't affect collision--touching them only has to change the state of the ninja from "alive" to "dead". Nothing special has to be done to determine the proper alignment, pose, position, etc. of the ninja when it touches a mine.

It's not impossible, just not readily implemented given the current state of things, like Maniac said.

Anyone more knowledgeable than me, please make necessary corrections.
