Read something in a book several years ago (a biography of mathematician Paul Erdos) that I found pretty interesting. Did you know that some infinities are larger than others? Here, I'll show you. My apologies if this explanation is a bit confusing, but here goes:

We define Set #1 as being the same size as Set #2 if every member of Set #1 corresponds to a member of Set #2. However, if there are members of Set #1 that don't have a corresponding member in Set #2, Set #1 is larger than Set #2.

For example, the set of all even numbers is the same size as the set of all integers (or whole numbers):

1-----2
2-----4
3-----6
4-----8
5-----10
Ad infinitum

And so is the set of all squares, all primes, and even all fractions. But is the set of all decimals the same size as the set of all integers? Say we could write out every single decimal number onto some very large sheet of paper (keep in mind that this is an infinite list of these numbers stretch on infinitely):

1-----.138109523652309486...
2-----.987234561439874569...
3-----.239847562348527952...
4-----.792345216084237695...
5-----.269875126125526341...
Ad infinitum

Now, what if we took the 1st decimal place in the first number, the 2nd decimal place in the second number, the 3rd decimal place in the third, ad infinitum, and made a number from that?:

.138109523652309486...
.987234561439874569...
.236847562348527952...
.792345216084237695...
.269875126125526341...
Ad infinitum

Makes:

.18637...

That's all well and good, but that number is also on our list. But what if we added 1 to each decimal place of the number?:

.18637...
+
.11111...
=
.29748..., our new number.

Now, this is the hardest part to wrap your head around, but stay with me. That number we just made is nowhere on our list. How do we know that? Well, we just go back and compare our new number to each number on our original list. Notice anything?

Look closer. Remember that the "2" in .29748... came from the first digit in our first number, which happened to be a "1", with 1 added onto it. See the problem there? There is no possible way that our new number could be the same as our first number, because that first digit is different.

In the same way, the "9" in our .29748... was taken from the second digit of the second number, which was an "8". They can't be the same number, either, because the second different is different. The same goes for the third digit of the third number, and for all of the rest of the numbers on our list. So, what does that mean?

Firstly, it means that our new number, .29748..., most definitely isn't on our list. But wait, wasn't our list supposed to have all of the possible decimal numbers on it? It was, but we seemed to have missed one. (And, by the way, we could go through that same little experiment again, and get an infinite number of numbers that weren't on the list.) That means there's a member of the Decimal Set that doesn't correspond to the Integer Set. Soo, that means...

The set of all decimals is larger than the set of all integers. We've come upon a larger infinity. The regular ol' integer infinity is also known by mathematicians as aleph-zero, and our newfangled decimal infinity is aleph-one.

And now we all have headaches. Happy fun time?

That makes sense... but doesn't it work for integer numbers, aswell?

In non-integers, written numbers can go all the way to infinity (left-to-right), getting smaller as they go. If the number stops, then you can assume that the rest of the numbers are 0, all the way to infinity (for example, if the 6th decimal on tktktk's list was 0.0234 exactly then for his his calculated numbers he would have had to use 0.023400, giving .186370 and .297481.

But written integer numbers also go to infinity (right to left), getting larger as they go. So you can take your numbers from right to left.

eg:
0002354
0232678
6590786
8198719
0000012

to get 08774 and 19885

In other words: I'd say that there was more infinity than can be imagined, so all proofs relating to it are a little bit... odd. For example, this proof requires even just the the idea of an infinite list of numbers, which is impossible.

#195103 16 2006-06-27T01:36:54Z Atilla
Things like this are the reason you have to be careful about saying things like infinity/infinity = 1. It's not neccesarily true, because infinity is a process rather than a number.

Consider the functions y=10x and z=5x. lim y as x-> infinity = infinity. lim z as x -> infinity = infinity. However (lim y)/(lim z) = 2, not 1. It's a common mistake in exams...
