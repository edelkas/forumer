#213857 2 2006-08-10T05:24:55Z Atilla
I'm not a developer as such, but I can tell you that C++ and BASIC are generally considered the most important to know, and are used for many professional projects. Java and HTML can also be useful, though mostly if you're intrested in some kind of web design.

To learn the languages? Dowload a compiler, download some tutorials, and spend a lot of time practicing and experimenting. Formal classes are useful, but not mandatory as such. I reccomend you take them, though.

Go for a degree if you're sure it's what you want to do. Start looking into university courses (look for "computer science", "software engineering" and "information systems"), and see which subjects are prerequisites. Make a few freeware applications - it increases your personal fame, and gives you an example of your prowess to wave at potential employers. Also, don't wait for someone else to approach you. Take an interest in some software companies, and mail them saying so. Remember that they'll like you a lot more if you can demonstrate that you are genuinely interested in their projects.
#213874 3 2006-08-10T08:42:02Z astro
Have a look through online job sites for anything you'd be interested in doing and see what kind of things you'd need. Generally, experience is the main thingfor the things I've looked at in terms of my own future career, anythingrather than degrees.

Also, I don't think it's that important to pick the most useful or widely used programming language when you're starting off learning. The most important thing is understanding the logic and style of programming (whether it be procedural, OOP, etc.). Once you've got good experience with that, you can diversify your programming knowledge, try out different languages, and see the difference. I also don't think formal lessons in programming are that great or useful, but it would all depend on your personal situation.

When it comes to learning languages, find some tutorials if possible, but I find the best resource is normally the official language reference. Books, too, are very good. Go to a library and see if you can find some.

Language-wise, I'd be looking at C, C++, Objective-C, Java, and something like Perl or Python.

#214557 14 2006-08-12T00:10:59Z Raigan
i'm not sure about the xcode/IB stuff, but i think both are just libraries/tools to help you make mac applications.

in general you write some source code in an editor, and then run that through a compiler which builds something you can run. i used to know about linking and all that stuff but it's all very hazy.

things like flash or processing are good because they make it really easy to get down to the interesting part, which is your specific game/idea. just getting a window open and drawing stuff in it, getting keyboard or mouse input, etc is a huge pain, and most people use libraries that have code that performs all of those tasks already written. SDL is a library one of our friends uses for his c++ games.

same thing with GUIs, there are libraries or you can build your own. same goes for reading/writing files.. you CAN do it all yourself from scratch but often it's a lot simpler to just use a library that's been well-tested.

the nice thing about processing is that it's sort of all-in-one (like flash) in that it provides you with an editor, a compiler, and a library that takes care of all the basic things.

one thing you could try, if you understand some of the basic ideas, is to download processing and look through the included example programs. that way you can sort of start learning by changing values or adding things to the code and seeing what happens.. if you have to start with a totally empty file it can be pretty intimidating, by fooling around with the examples you'll hopefully get more comfortable with the basics.
