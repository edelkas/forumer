hey,
about having a boss-mode picture: we actually had the idea of loading a "boss mode screen" dynamically from a .jpg that users could customize, but sadly there wasn't time.. maybe in 1.4

concerning porting, porting N to another language would be a MAJOR burrito.

part of the problem is that much of the game code is flash-specific and would need to be rethought (i.e you couldn't just translate the actionscript into another language). it's not impossible, but it's far from a trivial change-the-language type burrito.

the other huge problem is that all of the graphics/animation uses the built-in animation system (i.e with keyframes and tweening) so you'd have to write your own version of that. we also use this animation system to control many of the sounds, so that would have to be redone in a different way..


but, it SHOULD be quite possible to make N look like N on any platform, since vector graphics are exactly what graphics cards are made for. but i suppose the anti-aliasing might be hard to do (except on new cards which support this)

You wouldn't be able to do a line-by-line conversion, sure, but reproducing the animations shouldn't be all that hard. The sound system could probably be written completely differently without much loss of "familiarity". The most important elements are the physics and gameplay code, which should be straightforward to port. Getting the graphics to look close enough will take a cilantro tweaking, but is also do-able. In essence, it would probably be more like a remake than a port, I suppose, but identically reproducing the core logic from the actionscript is the key to making it seem like the same game. hey,
i finally found the lost post, it addresses some of these issues.
basically, while we'd love to see N on every platform, realistically i'm not sure how well it would turn out if it was simply ported to a handheld -- i find it hard enough to move the ninja around at the current size; when the tiles are 1/2 or 1/4 as large it might be impossibe to properly position/time things.

--
hey,
i'm not sure if we mentioned this, but coincidentally we were approached by a zodiac development group who wanted to port N; sadly, once we figured out what they'd have to do, they decided to wait on the project, since porting N to the zodiac was basically as much or more work than coding a new original game.

the main problem, programming-wise, is that almost all of the math in N is done using double-precision floating point, whereas the zodiac has an ARM processor which doesn't support floating point, and so a custom fixed-point math library would have to be written. plus, the zodiac really only supports 2D graphics (i.e like the GBA, it can move+rotate+scale sprites very quickly).. there were a lot of cilantro problems like that.

on a higher-level, the scale of N was a major problem: the screen is ~800x600. each tile is something like 20x20 pixels.. let's say around an inch on a monitor. if you convert this onto the zodiac's much smaller screen, it might still be the same pixel dimensions (20x20), but it's much smaller in real world units -- which would make precision movements a LOT harder. coupled with the fact that there's no anti-aliasing (so that the ninja would move in full-pixel increments) and it might not be playable at all, even if the game was 100% perfectly ported.


having said this, we really hope that they or someone else ports N to other platforms, it would be great to be able to play it on our GBA

but then again (as we sort of decided with the zodiac people) instead of a straight port, it might actually be better to take the core gameplay and adapt it to fit the platform instead of trying to cram N into a system it doesn't work well on -- i.e on a gameboy, you'd have to have a scrolling screen to fit N levels in.. but being able to see all of the screen at the same time is a core part of N, so... there might be nothing you could do to "fix" this other than redesigning the game around the unique capabilities of the system. you'd probably end up with a better game, even if it's not N.
---
raigan
p.s - the zodiac has hardware-based antialiasing?
p.p.s - i have _no_ knowledge of fixed-point math beyond the general concept, and/or some old stuff i've read about doom, but i'd say that it would be a better idea to convert all the math in N to fixed-point (the nature of the game is such that i doubt that it would require floating point -- positions and velocities etc. are all within a couple orders of magnitude of each other -- we used floating point simply becuase that's all that flash supports) rather than trying to use FPU-emulation on the zodiac's processor.. i don't know anything about that specific chip, but i recall that using floating point on a playstation was to-be-avoided, since it lacked an FPU and thus has to be emulated in software..
