#9164 1 2006-06-01T02:01:10Z Atilla
Previously it has been suggested that one might be able to create folders to keep userlevels organised. Instead, I propose that N be able to handle multiple text files instead of just userlevels.txt.

It would work like this. Instead of loading userlevels.txt when you enter the userlevels menu, there would be file called include.txt or somesuch, which would contain something like

&files=
"userlevels.txt"
"legacy.txt"
"LA^3.txt"
"atilla_and_co_training.txt"
"my_levels.txt"

The userlevels menu would parse this file, and display the file names like it currently does the levels (maybe descriptions/authors could also be included). Clicking on one of the files would then load the levels from that file as is currently done for userlevels.txt. Of course, a "change file" button would be added to the level menu, allowing you to go back and select a different one.

This seems technically feasible, and shouldn't require too much extra programming (particularly since you should be able to grab most of the code from the already-existing functions for parsing userlevels.txt). It would also have a large number of benefits - it would be *very* useful for level packs, it would let you keep things organised, it prevents parsing a large amount of unnecessary data, and it prevents me having to constantly rename a buch of text files. The only downside I can see is that it might be little confusing to newbies, but then, the current system isn't terribly user-friendly, either.

EDIT: Since it doesn't actually mess with the userlevels file, the level data, or the parsing itself, it would also be totally backwards compatible.

Thoughts, anyone? Is this impossible for some technical reason I haven't thought of? Is it just too much programming?
