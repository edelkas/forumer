#87021 3 2005-07-30T02:34:45Z Guest
there's really no way to answer the "why" question, there's no principle which points to doing things the way we've shown in the tutorial. certainly there are some problem cases where the projection vector isn't the one that looks/behaves the best.

the problem is that it's probably impossible to come up with consistant rules about what the "best" projection vector is. really, two objects in reality _never_ overlap, so there is no obvious "right" way to deal with this case in a computer simulation.

our approach is to say arbitrarily: when two objects overlap, the "best" way to fix it is to move the objects by the smallest amount possible so that they no longer overlap. this movement vector is sometimes called the minimum translation distance/vector (MTD), or the projection vector.

but you're right -- there's no reason why using the smallest projection vector is the right way to do it. in fact, as you pointed out, there are cases where using the smallest vector is NOT what you want. but coming up with rules about when to use what vector is hard..

projecting things out of each other using the MTD has no basis is physical reality, and often other approaches work just as well.
