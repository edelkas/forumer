hey,
it depends what you mean: do you want to be able to used shapes which are rotated to collide against, or do you want to simulate 2D "rigid bodies" (i.e shapes which not only change position based on physical rules, but also rotation).

the first is easy; how it's implemented depends on how you're rotating the object. if you use a matrix, then all you need to do is take the non-rotated axes you'd test for the object, and rotate them by the rotation matrix to get the new axes you should test.

(are you doing this in flash? if so, i'd suggest finding a simpler method, for instance rotated boxes are very fast to collide, if you store one of the box axes as a unit vector -- the axes to test are then that axis, and the axis perpendicular to it).

the second is hardER, but still possible in flash; i'd recommend implementing everything in the jakobsen paper we link to -- you'll end up being able to simulate the movement of rigid bodies in 2D. (see my horribly stale personal webpage for an example of this, it's linked from the metanet site's [about] page).

then, you need to have collision routines which not only return a projection vector, but also a point on each of the colliding shapes, the "contact point" (the points which will be touching when you project them apart). i suspect this is what you're asking about, and it's possible, but also MUCH harder and probably impossible to do fast enough for a game in flash.

however, again, if you limit the possibilities (for instance, by using basic shapes like rotated boxes instead of arbitrary shapes) it can work. if we have time we're going to add stuff about 2D rigid-body simulation (i.e finding the contact point) to the last tutorial, we've got 2 or 3 "demos" if it working, but they all have problems.

thanks,
raigan
