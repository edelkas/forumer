Hey, sorry for not answering for a long while, I was abroad. Anyway, here's the relevant code I now use for terrain-following. It's far from flawless, however, I'm still having trouble finding some problems but I'm sure it'll be fine.

        Line line = new Line(fromX,fromY,toX,toY); //Creating the line from start to end
        int movementPoints = line.getPoints().size(); //The length of the movement line
        int pointsMoved = 0; //The number of points moved
        Iterator<Point> pointsItr = line.getPoints().iterator();
        double lastGoodX = fromX, lastGoodY = fromY;
        while (pointsItr.hasNext() && pointsMoved<=movementPoints) {
            pointsMoved++; //Increasing the number of points moved
            Point p = pointsItr.next(); //Getting the next point
            obj.x=p.x; //Moving the object
            obj.y=p.y; //along both axes
            adjustToBounds(obj); //Adjusting the object so that it won't go outside the world's bounds
            if (submergedInGround(obj)) {
                int stepSize=0; //How high the player climbed
                do {
                    obj.y--;
                    stepSize++;
                } while (obj.y>1 && submergedInGround(obj)); //Making sure the object isn't stuck underground
                adjustToBounds(obj);
                if (stepSize>Player.maxStep) {//The slope was too steep
                    obj.x=lastGoodX;
                    obj.y=lastGoodY;
                    return;
                }
                //The slope was fine, but now the line needs re-adjustment
                line = new Line(obj.x,obj.y,toX,toY+obj.y-fromY);
                pointsItr = line.getPoints().iterator();
                pointsItr.next();
            }
            else {
                lastGoodX = obj.x;
                lastGoodY = obj.y;
            }
            while (obj.y<height-obj.height-1 && submergedInCeiling(obj)) {
                obj.y++;
            }
            Direction submergeDirection = submergedInWall(obj);
            if (submergeDirection==Direction.LEFT) {
                do {
                    obj.x++;
                } while (obj.x<width-obj.width-1 && submergedInWall(obj)==Direction.LEFT);
            }
            else if (submergeDirection==Direction.RIGHT) {
                do {
                    obj.x--;
                } while (obj.x>1 && submergedInWall(obj)==Direction.RIGHT);
            }
            adjustToBounds(obj);
        }

#333546 12 2007-06-20T16:57:30Z Derakon
For what it's worth, when terrain-following, almost always you'll want to push the object out along the surface normal of the terrain. This gives you automatic "it's slower to climb up hills than to walk along flat ground", and is in general more accurate. The only time I've found when you want to avoid this is when the sprite is standing still on slanted ground. Gravity will push the sprite down a bit into the terrain each frame, but if you then push the sprite out along the terrain's surface normal, it'll gradually slide down the slope. So in my game I've hacked the sprite to specifically check for when its X velocity is small and its Y velocity is aligned with gravity, and push it out along its velocity vector instead in those situations.

My problem right now is figuring out how to get the sprite to run down slopes when the downward velocity would be faster than gravity.
