Quote: mattk210, December 02, 2007 04:46 pm
Internet Explorer can display XHTML can't it? my website is XHTML and it displays fine

EDIT: according to the tag on the bottom and the doctype, the w3c site itself is written in valid XHTML, and it works in IE6 and 7
You would be 'serving' your website as .html (text/html) and so all the browsers will interpret it as regular HTML. To be properly parsed as XHTML it needs to be served as XML (application/xhtml+xml) [I'm referring to internet media types]. See the XHTML Media Types document from the W3C: "XHTML documents served as 'text/html' will not be processed as XML [XML10], e.g. well-formedness errors may not be detected by user agents".

Your XHTML may be 'valid', but the code is not necessarily well-formed XML. Either way, IE wouldn't be able to display it as XML.

Quote: mattk210, December 02, 2007 06:38 pm
so the w3c itself doesn't use application/xhtml+xml?
Hmm, it doesn't seem to, no. Probably in the interests of compatibility--on that media types page, for example, it's by default XHTML served as HTML, but it has links (under 'this version') for HTML and XHTML (as XML) versions. If you try opening the proper XHTML version in Internet Explorer it fails and asks you to download it instead.

edit: the plot thickens. Their media types summary says that text/html 'may' be used for XHTML 1.0 (HTML compatible). Furthermore,
Quote
The use of 'text/html' for XHTML SHOULD be limited for the purpose of rendering on existing HTML user agents, and SHOULD be limited to [XHTML1] documents which follow the HTML Compatibility Guidelines. In particular, 'text/html' is NOT suitable for XHTML Family document types that adds elements and attributes from foreign namespaces, such as XHTML+MathML [XHTML+MathML].
In other words, they say it's alright (although not explicitly recommended) to serve your XHTML 1.0 as text/html (eg. do what most people are doing with XHTML) so that people with only HTML browsers can view it if you follow the HTML Compatibility Guidelines. However, the Beware of XHTML article does discuss this and says that
a) many people think these compatibility guidelines shouldn't have been made, and
b) XHTML 1.1 removes this provision entirely and states that it should not be sent as text/html.
