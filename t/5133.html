I couldn't find a thread for this by searching so here goes:

Probably Mare and Raigan are already working on something like this in the "better integration with NUMA" and "robust file system" area but I was thinking how the organisation of levels in the user level list in N could be improved so I thought I'd throw the idea in for discussion.

The main problem for me is that while by default there are only a hundred and fifty levels in the User Levels section, if I start copying maps from NUMA I like to play into the userlevels document, the list quickly grows and after a while it gets quite hectic, especially with the many thousands of levels now in NUMA.

I wonder if a sort of a folder structure could be devised for the user level section. Concrete folders aren't needed but some sort of grouping into categories would be good, either by simply sorting levels into folders by author, type (Action, DDA, Easy, Hard, etc.) or level title, or by another grouping system I haven't thought of. The goal would be that you wouldn't have to browse through a very very long list every time you wanted to play a user level, but rather you could choose a category (or any item of the grouping in question) and go forward from there.

I wonder if you have got any other ideas for the possible improvement of the way levels are organised in the user levels section.

Initially I was thinking along the lines of pre-set folders.

Quote: Maniac, 2005-10-09T21:43:22Z
You can sort the list as such, but wouldn't folders be a lot easier?

Depends on what kind of folders we are speaking about. I was thinking of pre-set folders based on type / author, etc., which would be almost equal to a sorting system. Let me explain. If you go into the User levels menu, you would see the initial "folders" (sorting categories), from which you can decide a way to select which type of levels you want shown.
Example 1. If you want to search by author, you can click the Author "folder" and then the program compiles a list for you from the userlevels.txt (if N 1.5 keeps the data in one txt) and sorts levels according to username. You pick a username, then you pick a level from the levels under that username.
Example 2. Similarly, if you want to view, say, DDA's, you can click the Type (folder), then you get the list of types (it may be a good idea, though, to have more types than Action, Puzzle, Hard, DDA, Test and Incomplete as hundreds of levels fall into the first three categories each), then you get the list of levels of the selected type.
In this version, levels would not really be in actual folders so they could overlap in the lists.

The other version is your idea, self-managed folders. I didn't think of that, but that could really be messy if you make too many folders. That's why I'd go with a pre-set folders (with an extra folder for your own levels), with perhaps a "Favorite" setting to have a place where you can link your favourite levels from either category, similarly to NUMA.

I was thinking along the lines of working with pre-set levels because I have another idea in mind which would concern downloading levels to your game by avoiding copy-pasting, and more rather getting levels into N simply by downloading them from NUMA. I just didn't post that idea yet because I haven't worked out how exactly that could be handled.
