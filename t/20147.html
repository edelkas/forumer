#379489 2 2007-11-14T23:53:52Z Raigan
If i remember correctly, the tiles are drawn in "retained mode" (i.e you create the graphics object once and Flash draws it each frame), and the moving object/ray/etc are drawn in "immediate mode" (you need to call a draw function each frame). Retained/immediate is just a metaphor for how things work, which parallels the similarly named usage idioms for openGL.

This should be a pretty simple thing to swap out, one way to do this would be to always call each object's .Draw() function each frame. If you want an object to use the retained-mode paradigm, you just need to make sure it constructs its graphics when it's created (via attachMovieClip() or similar), and then it can position/rotate/etc the movieclip inside its Draw() function. For immediate-mode objects, you can simply do nothing on creation and draw to a shared empty movieclip in the .Draw() function.

This sort of thing is definitely something we're still learning a lot about though, designing the structure of the program and how the various systems interact is a lot more involved than solving specific problems like collision!

#379714 5 2007-11-15T17:24:07Z Raigan
well, it depends on how you look at it -- in a c++ game there are both layers at work, since the game code may be using a retained-mode approach (i.e load the 3D model at the start of the level, and then just change position/orientation each frame; the rendering system will draw the model appropriately) while the lower level rendering code _is_ drawing it each frame from scratch (i.e telling openGL to draw a bunch of triangles). you could just have the game code calling openGL, but it's usually a good idea to have an intermediate layer so that you can for instance change to directX without having to dig through your whole game.

in flash it's just confusing because the lower-level stuff is already written. for any object that's using a movieclip for graphics, it makes sense to just attach it once and then position it each frame.
