This is a really cool (and free!) fractal program I found: Context Free.

You can either play with examples or learn the language, which is not too hard; here's a little info:

You have to start with 
startshape flower
or whatever the initial shape to draw is. You define shapes (rules) this way:
startshape flower

rule flower {
	// code goes here
}
All shapes are basically made of squares, triangles, and circles. You make those like this:
startshape flower

rule flower {
	SQUARE{}
	TRIANGLE{}
	CIRCLE{}
}
When you draw shapes, you can give them properties. For example, this makes a square rotated 45 degrees:
startshape flower

rule flower {
	SQUARE{r 45}
}
and this makes the same square, 3 times bigger:
startshape flower

rule flower {
	SQUARE{r 45 s 3}
}

So now you see the basic way of modifying the simple shapes. These are some of the properties you can use:
y: shifts shape on the y-axis
x: shifts shape on the x-axis
s: size
r: rotation
hue: hue, from 0-255
sat: saturation, from 0-1
b: brightness, from 0-1
a: alpha (transparency)
skew: to skew a shape, can take 1 or 2 parameters ("skew 10" or "skew 10 25" or something like that)
flip: flips the shape across a line positioned at the number of degrees specified

Now, suppose you want to draw more than just one shape; let's say a tower of squares that shrinks as it gets taller. Well, to do that, you'd write:
startshape flower

rule flower {
	SQUARE{}
	flower{y 1 s 0.99}
}
This will draw a square, then execute the flower rule again, but shifted up one unit and at 99% of the size. Context Free only renders shapes until they are too small to see. This means that it will not render the above code forever, only until it gets small enough to be invisible.

How about curves? Just add an "r 1" after "y 1 s 0.99" in the above adjustments for the flower rule.

Of course, if you want to make a tree, you're not just going to have a single line. You'd want branches, right? But how would you make them besides randomness?
startshape flower

rule flower 1 {
	SQUARE{}
	flower{y 1 s 0.99}
}
rule flower 0.1 {
	SQUARE{}
	flower{y 1 s 0.99}
	flower{y 1 s 0.5 r 45}
}
Notice the addition of numbers after the name of the rule you're defining ("rule flower 1" and "rule flower 0.1"): these set the probability for each version of a rule. In this case, the second definition of flower is 10 times less likely to be used than the first. But each time it's called, that rule will do one of those two things. Another thing to notice is that the second definition draws a flower twice: once to continue the original "trunk" of the tree, and the other for a branch. So, if you render the above, you'd get something to the effect of:


Oh, noes! We only have half a tree! Why is this? Well, because we never defined a rule for the tree to go the other direction. Let's.
startshape flower

rule flower 1 {
	SQUARE{}
	flower{y 1 s 0.99}
}
rule flower 0.1 {
	SQUARE{}
	flower{y 1 s 0.99}
	flower{y 1 s 0.5 r 45}
}
rule flower 0.1 {
	SQUARE{}
	flower{y 1 s 0.99}
	flower{y 1 s 0.5 r -45}
}
Now we've added a third rule just as likely as the second one, but it rotates the other direction. Let's render:

Whee, a tree!

Now, go download Context Free and render this:
startshape init

rule init{
	tree{}
}

rule tree 1{
	SQUARE{}
	tree {y 1 s .99 r 1}
}

rule tree .01 {
	SQUARE{}
	tree {y 1 s .99 r 1}
	tree {y 1 s .99 flip 90}
}

rule tree .01 {
	SQUARE{}
	tree {y 1 s .99 r 1}
	tree {y 1 s .6}
}
You'll get a very special swirly tree!
