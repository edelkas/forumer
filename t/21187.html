If you want a game, but don't know where to start, chances are that you aren't ready to start making one yet. Many developers always think "oh, I'll learn as I go" - no. Please no.

Go and read up on some how-to books and documentation on C+ and learn it's basic command calls. Once you've got that, go search Google for a tutorial on C++ game making.

Even moreso, to get into the atmosphere of game coding and command calls, try out GameMaker. It has a "Free" demo version so you can get attuned to coding, since you're apparently far, far away from the steps required to make a game.

Trust me, mate; I'm a developer, myself. It is a hell of a lot of work to make a game. Not even knowing a code language, or a code to start learning, isn't a good thing. Through hard work do beautiful things arise, mate.

Money=Quality. If you're going to try to find a free method to developing a game with minimal effort, you won't get far.

#402525 7 2008-01-21T01:50:15Z Jason
If you think you are up to learning ActionScript 3.0, go here:

http://www.senocular.com/flash/tutorials/as3withmxmlc/

You can download the free trial of flex, and get the exe needed to compile AS files. If you want to import vector art, you will have to get some other program, I haven't looked into it. But with these tutorials, you can import bitmaps for your graphics. If you want more complicated behavior like animated sprites, you will have to go inline and find more ActionScript 3.0 tutorials. Mainly though you would want to steer clear of Flash 9 tutorials, because you won't have CS3 to work with, thus you will not be able to make movie clips. Also you will have to find some editor to make AS files in, any text editor will do, but if you find something better, go for it.

#455755 31 2008-07-29T09:26:46Z Decoy
There are pretty much four languages you should ever program in.

C++ if you want to make anything that needs to run really fast (real-time 3D games for example).

Python if you want to process information.

Java if you want to make web applications or less computationally-intensive games.

Actionscript if you don't give a damn about efficiency but really hate trying to add drawing capabilities to any of the above languages.

Just about everything else is either specialised or trash.* I'd be delighted to be proved wrong.

*For modern programming tasks.
