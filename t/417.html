#23886 6 2004-06-25T17:32:29Z Guest
hey,
well.. this is going to be hard to explain.

the first problem is that most of the shapes you're suggesting amount to doubling the resolution of the grid -- i.e the 1/4-size shapes you want are equivalent to using the current set of tiles, but shrinking the grid size.

this can't happen, since the smaller the grid, the more tiles, the more vectors to draw, the slower things go. right now the grid is ~20x25 tiles (i think), which is 500 tiles. each tile is ~4 "curves" which the renderer needs to draw, which means 2000 curves. right now it manages this without too much of a slowdown, BUT if you add lots of objects, this increases the number of curves -- and at some point the renderer can't handle it. we haven't managed to find this point exactly, but there's definitely a cutoff where the performance suddenly drops.

now, imagine we used a smaller grid; this would be 40x50 tiles, which is 2000 tiles. which would mean 8000 curves.. too slow

the idea is a good one -- we've both wished that we had 1/4-size tiles since it would allow many more possibilities. but as it is, N barely runs fast enough. this is a case of: we'd implement it if it were possible, but the flashplayer just can't handle it. during testing we found that even a 30x40 grid was too slow.



the second problem is that, because of how the engine/collision works, we don't have any way of knowing what is a 'ledge' and what isn't.. this makes the hanging-off-ledges thing impossible. but i agree that it's a really fun idea!

raigan
p.s - don't despair -- having learnt from making N, our next engine will definitely support more types of interaction with the world, such as hanging/etc..
