Obviously, I prefer OSX over (in this order) Ubuntu Linux, Vista, other Linux, XP, the rest. Since this is largely a matter of prefernce, I will not comment on the WHY. However, let's consider the technical side:

The largest drawback of Windows is its backward compatibility. While it is great to have, it limits the technological progress of the platform considerably. Both the Win32-API and GDI essentially are very old technologies that really cause a lot of trouble. This is not saying that backward compatibility is a bad thing per se, but every few years it sould be time to move on. Now this is a difficult thing to do if you simultaneously have to support millions of legacy applications, but still it is even more futile to instead stop moving forward.
Of course, MS DID move on and provided new technologies and libraries but as it turns out, the number of developers not using newer code is just unbearable. (This is what UAC is all about: annoy users in order to persuade *developers* to for once respect user rights!) Also, as GDI is old and crappy, it lead to an enormous diversity of built-on-top UI widgets, which in effect make every application look and work suptly different. This actually is the greatest critiscism on the Windows GUI: As everything looks and works different, there just is no way to make a standard-conformant application.
However, Vista really and vastly improved on many of those aspects. Let's hope that Windows 7 will continue to bring fresh ideas and more conformity to the Windows platform.

On the contrary, OSX is well known to make really huge changes in its design without neccesarily breaking the OS. This happened with the switch from PPC to Intel, from Carbon to Cocoa (soon), from 32 Bit to 64 Bit, from BIOS to EFI, with the inclusion of the OSS kernel and some other stuff. This makes the platform VERY interesting to developers, as it is filled with really interesting, cutting edge technology. However, it of course limits backward compatibility to roundabout 5 years. This really is the price you pay as a developer.
As far as user experience is concerned, Apple has VERY strong human Human Interface Guidelines that are both followed by users and developers which makes the whole Mac experience very consistent and -mostly- easy.
On the other hand, you are really stuck if "The Mac Way" just doesn't work for you. In that case, customizability is very hard to come by, as it -while not technically difficult- simply is not desired by either the userbase or the developers.
The next release of OSX, Snow Leopard, will feature some really increadible new technologies (OpenCL, ZFS, just to name two) that many a developer will be craving to use.

Now lets consider Linux: Linux is a largely community-written effort to create an operating system. While this approach really only limits the possibilites by the developers' imaginations, it also creates a whole lot of redundant work and plain "noise", which somewhat blurres the very neat platform. Technology-wise there are lots of really cutting-edge sections of the source code that even go a lot farther than OSX in some places. However, at the same time there are many (boring) parts of Linux that really are even more outmoded than the W32-API. Somewhere in between lies the true nature of Linux.
As for the UI, there are two major schools of GUI-design, KDE (Qt) and Gnome (Gtk), both of which try to make their respective applications work consistently and simple. In the last few years, tremendous efforts were taken to accomplish a "desktop-readiness" similar to Windows XP or OSX. Again, there are places where this really works, while others still look like stone age. We see a pattern emerge.
For developers, Linux is very interesting, but sadly has only very limited economic possibilities, which probably hinders a larger adoption as a mainstream platform. However, this has never been the goal of Linux, so this is probably not a problem.

I tried not to say too much about the actual user experience, as it is really a matter of preference. But take my word, it is quite possible to be productive on either platform.
Just one little warning: It takes time to unlearn and relearn how to operate your computer. You really can not comment on the user experience of an OS if you did not use it consistently for more than, say, three months.

At any rate, have a nice life!

Lets get strait what I meant:

Windows' model for backward compatibility is that even though they keep to develop their toolkits, they still keep all the older functions for legacy reasons. So while the library does get more modern, all the older, less good code is still in. (Of course it still gets deprecated at some point, but it is kept alive rather long). That way, the W32 API got as big and ugly as it is: There are many functions that provide similar functionality, they all use differnet calling conventions, code styles and notations. This is confusing, to say the least.
However, it still means that Windows is actually BETTER at providing backward compatibility than its competitors.

We can see such a transition in OSX at the moment, though in a much cleaner way: For years, OSX used a library called Carbon to draw windows. Then, they invented this rather more modern, MVC-powered, more sleek and just plain better replacement called Cocoa, that used more modern paradigms and thus was dubbed The New Way to draw windows.
But instead of integrating this thing in the old libraries, they started a fresh sheat but maintained both possibilities to ease the transition. With the next iteration of OSX, development for Carbon will be limited to bugfixes and there will be no 64-Bit version of it. That way, every Carbon-based application will definitly stop working at some point, but developers have plenty of time to port their GUIs from Carbon to Cocoa.

Now, there are advantages for both ways. Kind of like the difference between evolution and revolution. However, the Apple way avoids an awful lot of cruft and provides a much cleaner cut.

As for the deepness of cuts, OSX was a complete new OS. It was a complete new codebase, based on the Next-kernel. This is about as deep a cut as it gets. Such a thing essentially never happened anywhere anytime at all. Since then, Apple has been known to have lost fear of grand revolutions, while the rest of the software world rather relies on evolution instead.
