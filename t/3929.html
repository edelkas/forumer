Sorry I'm late, but I'm not so active on these forums nowadays. This will be the longest post I've written, so get ready.
For the source:
Oh, boy. We have some fixing to do.
Judging by the Flash Player publishing version you're using Flash MX 2004. Therefore, you can use some little optimizations that came with Flash MX:
  • USE INTERVALS! Dammit, they're much more easier to work with! I haven't used (or seen anyone use for that matter) onClipEvent for about 2 years or so! (since Flash MX was released)
  • Look at the attached file, that's how particle physics is supposed to be done (well, at least with vertlet integration )
  • Forget about per-movieclip actions!
  • Working code = first; Fancy graphics = later!
Now, let's start from the ground up.
First, you have Particles, each particle has the following properties:
  • .x - which is obvious;
  • .y - obvious;
  • .oldx - the previous x position of the object;
  • .oldy - the previous y position of the object;
  • .vx - obvious;
  • .vy - obvious;
  • .mass - this is almost too obvious;
    (next is the not so obvious properties)
  • .sList[] - in this array property you store references ("shortcuts") to the particles that the current particle is connected to;
  • .rList[] - this array holds the rest-lengths
  • .sid - this is the interval ID. I can use this to "stop" the particle whenever I want to (look up clearInterval() in the help panel).
So we have the basic relaxation function, and another relaxation function, that's not so basic. It's hard to explain what exactly the second one does differently from the first, but let's just say that it makes the movie work most of the times (instead some of the times).

Next, we have the most important function in the whole source file: the tick() function. This function is executed every 10 milliseconds or so, and it basicly does what your onClipEvent(enterFrame) is supposed to do, but much more times per second. In the function you do the collision with the stage(friction and bounce) and the relaxation, of course.

And last, but not least, we have the addStick() function. It connects the particles together and it sets the rest length between each connected pair.

SO, that's about the particle object. Now, you make a movieclip that the will actually "represent" the particles on the stage (i.e a black dot). Then yo give it a linkage name (i.e "point"). And finally, yuo do this:

Object.registerClass("point", Particle);

Here, Particle is what the Particle object is called.

After you call that line, every object that you "attach" (look up attachMovie() in the flash help panel) will be a particle. You connect the particles with the addStick() function and TADA you have a ragdoll.

#91595 19 2005-08-16T11:41:19Z shoftee
LOL. The thing is that when you set the particle's mass to 0, the relaxation doesn't move it, because when it multiplies invmass by something and invmass is zero, the overall result will be zero, so the velocity doesn't change.
So the idea is to make a new Boolean property for each particle, let's name it, "dragged" and when you press on a particle you set this dragged property to true and set the particle's mass to 0. When you release it, you set it back to false.
Then in your relaxation function, you make an if-else statement, so the relaxation is in the "else". Instead of "relaxing" it, while the mouse is down, you set the x and y coordinates of the dragged particle to _root._xmouse and _root._ymouse accordingly.
I think that should work, although I haven't tested it.
Hope that helps.
