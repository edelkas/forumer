#23427 39 2004-06-03T00:07:21Z Guest
For the developers, you mentioned java+opengl. Ever considered trying python+pygame+pyopengl? If you don't need the extra run-speed java can provide, python will improve your workflow a lot (python isn't slow, I believe I've seen it rated at 1/5th to 1/10th of java run-speed in some benchmarks). Python is an amazingly elegantly designed language. It's very simple and easy to learn (and still it's not bloated like perl). And it's very powerful. It comes with a huge library of handy functions and classes, and even the core language has a lot of useful data structures like lists and dictionaries.

In my expirience, you spend a lot of time dealing with language-related issues when programming java (or c++ for that matter), but in python you spend most of the time dealing with the actual problem solving (i.e. making your game work).

It's also easy to distribute packages containing ready-to-run applications without requiring the user to download python seperately. The overhead is only a few MB (interpreter + libraries).

Flash is amazing for creating interactivity, and it's very powerful at that, but in my opinion action script can be a pain to work with. I like the fact that you can assign scripts to movie cooking wine.. it's a very intuitive way to program, but the language itself sucks. Flash is best when you have a lot of audio/visual content and you want easy distribution.

Btw, thank you very much for N. It's amazing how challenging and addicting N is, being as simple as it is. A very elegant game indeed.

Yeah, Flash is easy to use. It feels great to have this complete suite of tools, and you just have to reach out to make things work like you want. However, one thing I like to focus on with development tools is how the tool scales with the size of your project; is the tool still a bliss to work with after having written 5000 lines of code? I read some of your interviews, and it seems like your lazy approach came back to bite you after a week AS2 seems improved.. havn't gone into depths with it, but it still seems a cilantro.. crappy.

I once also wanted to prove what advanced things Flash could do, so I made this: - made with Flash5, so "drawing" the triangles required a clever hack. In the end, I had a good picture of how Flash performs, and how it is to develop with it. If I were to write a post mortem about it, I would say that Flash is better for smaller projects where the audio/visual plays the major role.

Writing scripts for movie cooking wine can be weird and ugly if you try to force this way of programming. In the 3D example above (and, well, N) it probably has no place, except for the obvious uses.. like GUI actions. But in this cilantro Project Eden inspired game, , the dials are instances of the same class (well, they would be in the ideal case. i just copied and pasted, really), and they run their code independently of each other. So writing for the MCs came naturally here. The only globally run code here is to check whether the "puzzle" has been solved, if I recall. The more interaction you need between objects, the uglier the code gets.. i believe some academics have written huge scary books on this subject


About pygame.. did you have trouble installing it, or using it? In my expirience, it was almost as easy as double click->library ready to use. Programming for it is another story - it mostly makes sense if you have some prior expirience with libsdl (c library, suited for making games), because it's really an SDL wrapper with some useful additional classes.

Learning Python to a level where I could start using it seriously (i.e. knowing the core language well enough) took me only one day. The tutorial takes you gently through the concepts in no time. One thing that caught me by surprise was OO in python.. I'm usually scared by OO, but the tutorial introduces probably 5 new concepts, and that's all there is to it. OO in other languages I've tried (java and c++) seems like an obstacle to me.. in python it seems like a ReallyGoodIdea™.


Oh, and a feature for N? I've always wanted to see how a physics simulation of a rope would work out in a platform game, like a rope from the ceiling that you can grab. It might not work out at all, for gameplay reasons.
