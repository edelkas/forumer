#39019 26 2004-12-02T03:46:04Z HeartView
With the number of maps added to NUMA daily, I doubt that would work well. You WOULD have to come up with a way add maps to that list.

However, you could create a table that has a record for each map for each user, but only when that user flags a map as being played (manually on NUMA). The table would have 2 fields: User Name & Map #. No, this wouldn't be the most user friendly thing, but it would be a lot easier on the server.

I see it working like this: Take the total # of maps currently out there, grab a random value from 1 to that number, check if the map exists (could be deleted), check to see if there is a record in this table matching that map number and the user. If so, repeat this process until it finds one that they haven't played. Give the user the option to wipe their slate clean and delete all of their records in this table. The table would get bigger the more people use it, but not too big to worry about, I would think.

Anyway, just a thought.
#39038 27 2004-12-02T04:58:42Z Rahl
If he's gonna do that, a it would be a BAD idea to keep generating random numbers each time one isn't viable. Just generate one random number, if that one doesn't work (deleted, not in the list, whatever), increment the number by one. If the number > last map in numa, set to 1. That way you won't have any infinate loops as long as at least ONE map meets the criteria.

Otherwise what could happen is this: random number is 5, doesn't work, new random number is 7, doesn't work, new random number is 5, doesn't work, new random number is 7, doesn't work... and so on. More likely it would go through MANY numbers rather than two, but this is still quite possible.
#39105 28 2004-12-02T12:44:36Z HeartView
The only time there should be missing numbers is with deleted maps. Remembering which ones are deleted and which ones are not would be too memory intensive (depending on site traffic). I agree that incrementing the number might get you there faster, but you are still talking multiple searches into the database since you have to locate the record. Likely, it would be a SELECT statement attempting to return a single record, and would have to be re-run for each new record it is attempting to retrieve. So, not really any savings through either method, especially once the # of maps gets very large.
#39159 29 2004-12-02T23:18:48Z Rahl
No, the savings comes from the fact that with new random numbers each time, it can (and will. Trust me.) pick the same one more than one time. This can cause it to wind up doing an infinate number of searches, whereas the incrementing way is limited to the number of incorrect possibilities + 1. For the record, I don't really think that either is a very good idea, but new randoms is a REALLY bad one.
